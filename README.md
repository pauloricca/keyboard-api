# Keyboard Graphics API

A stateless, deterministic Node.js/TypeScript service for piano teaching graphics. One GET URL produces a complete keyboard image with a title, stacked keyboards, explicit highlighted notes, hand legends, and optional common-tone emphasis.

SVG is the canonical render. PNG output uses the exact same SVG internally and rasterizes it, so both formats share one layout/rendering implementation.

## Run with Docker

```sh
docker compose up --build -d
```

Open [Keyboard Studio](http://localhost:3000/editor), [health](http://localhost:3000/health), or one of the API examples below. The service listens on port 3000. Compose restarts it unless stopped and checks `/health`. No volumes or database are needed.

```sh
docker compose down
```

The Docker image installs `rsvg-convert` for SVG-to-PNG conversion.

## Visual editor

Open [Keyboard Studio](http://localhost:3000/editor) (also linked from `/`). It starts with one blank keyboard. Set the title, subtitle, shared note range, and note-name visibility. Each layout has a clickable keyboard: choose Left hand, Right hand, Generic, or Emphasis, then click keys to toggle them.

Add or remove layouts up to the 16-layout limit. Chord matching uses Tonal’s chord dictionary. The editor can suggest chord labels, consider the surrounding progression when estimating a key, retain inversions/slash basses, and let you replace automatic names with your own labels. Press Play to hear the selected notes with a short stagger.

The API URL updates live. The editor currently generates the default SVG form of the `/render` endpoint. Copy the URL to share it, or generate and download the SVG preview.

## Local development

Node.js 22 or later:

```sh
npm ci
npm test
npm run build
npm start
```

`npm run dev` builds browser assets and enables server reloads. Run `npm run build` again after changing browser modules. Set `PORT` to change the local server port.

SVG works with only the Node dependencies. PNG rendering additionally requires the `rsvg-convert` executable. Docker installs it automatically. For local development, install librsvg/rsvg-convert using your platform package manager.

## API

### Endpoint

```text
GET /render
```

`/render` replaces the old `/render.svg` path. The old `.svg` route is intentionally not kept as an alias.

With no query parameters, `/render` returns plain-text API instructions. With render parameters it returns an image.

### Output format

| Parameter | Meaning | Default / limit |
| --- | --- | --- |
| `format` | `svg` or `png` | `svg` |
| `title` | Overall heading | Optional; 120 characters |
| `subtitle` | Overall subheading | Optional; 200 characters |
| `from`, `to` | Inclusive shared keyboard range | C3–C5; ordered within A0–C8 |
| `chords` | Pipe-separated display labels; never inferred voicings | Optional; 80 characters each |
| `notes` | Generic highlighted note groups | Optional |
| `lh`, `rh` | Left/right hand note groups | Optional |
| `emphasize` | Global comma-separated notes, or pipe-separated groups | Optional |
| `labels` | Note names on highlighted keys and reference Cs | `true`; accepts true/false/1/0 |

SVG is returned as `image/svg+xml; charset=utf-8`. PNG is returned as `image/png`. Both responses include:

```text
Cache-Control: public, max-age=86400
```

PNG is generated by first producing the normal SVG and then passing that SVG through `rsvg-convert`. There is no separate PNG drawing implementation.

### Diagram syntax

Use `|` between diagrams and `,` between notes. All supplied `chords`/`notes`/`lh`/`rh` lists must have the same number of groups; use empty groups for rests, for example:

```text
lh=C3||G3
```

A single `emphasize` group applies to every diagram. Maximums are 16 diagrams, 88 note tokens per group, and 16 KiB of encoded query text. With no note/chord groups supplied, one unhighlighted keyboard is drawn.

Use uppercase note letters and optional `b` or `#` accidentals, such as `Db4` and `C#4`. Enharmonic duplicates inside a group are collapsed, retaining the first spelling. Encode `#` as `%23` in URLs, otherwise browsers treat it as a fragment. `URLSearchParams` is recommended for generated links.

Unknown query parameters are ignored. This allows tracking/share parameters such as `utm_source` to be appended without breaking an otherwise valid render. Recognized duplicate parameters and malformed recognized values still return HTTP 400.

Highlight precedence is emphasis, right hand, left hand, then generic. Both hand memberships remain in legends when groups overlap. Labels on keys preserve the winning group’s spelling.

## Copy/paste examples

SVG by default:

```text
http://localhost:3000/render?title=C%20major&chords=C&notes=C4,E4,G4
```

Explicit SVG:

```text
http://localhost:3000/render?format=svg&title=Three%20chords&chords=C%7CF%7CG&notes=C4,E4,G4%7CF3,A3,C4%7CG3,B3,D4
```

PNG using the same renderer:

```text
http://localhost:3000/render?format=png&title=C%20major&chords=C&notes=C4,E4,G4
```

Separate hands and common-tone emphasis:

```text
http://localhost:3000/render?title=Everything%20In%20Its%20Right%20Place&subtitle=Main%20keyboard%20voicings&from=C3&to=C5&chords=C%7CDbmaj7%7CEb6&lh=C3,G3%7CDb3,Ab3%7CEb3,Bb3&rh=C4,E4,G4%7CC4,F4,Ab4%7CC4,G4,Bb4&emphasize=C4
```

Embed either output URL in an HTML `<img>` (escape ampersands as `&amp;` in HTML), open it directly, or save it with curl:

```sh
curl -o lesson.svg 'http://localhost:3000/render?title=C%20major&chords=C&notes=C4,E4,G4'
curl -o lesson.png 'http://localhost:3000/render?format=png&title=C%20major&chords=C&notes=C4,E4,G4'
```

## Current limitations

The renderer uses a vertical layout, fixed colours, and explicit caller-supplied notes. The editor suggests chord labels, but the rendering API does not infer notes from chord names. There is no POST endpoint, authentication, database, or persistent storage. Output uses system Arial/Helvetica/sans-serif fonts, so text appearance can vary slightly by SVG viewer or rasterizer while the keyboard geometry and note placement remain deterministic.
